# Contributing to searsuite-website

Thanks for contributing. Start with the [repository README](https://github.com/SearSuite/searsuite-website#readme) and [versioning policy](VERSIONING.md).

## Before you start

- Search existing issues and pull requests. For substantial API or behavior changes, open a proposal issue first.
- Keep changes scoped to the owning package and use public package entry points for cross-package imports.
- Follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Make a change

1. Create a branch from the default branch and install dependencies as described in the README.
2. Add or update tests when behavior changes. Run the relevant build, tests, and repository checks before opening a pull request.
3. Update package README and public API documentation when behavior or usage changes. Record user-visible changes in the **Unreleased** section of `CHANGELOG.md`; mention compatibility impact.
4. Open a pull request using the template. Link the issue, summarize the change, and include the commands run and any remaining limitations.

Maintainers review scope, correctness, API compatibility, documentation, and test evidence. Reviews and merge timing depend on maintainer availability.
